<objective>
Implement MGMT-01 service-layer chokepoint in `services/brand_service.py`:
1. Evolve `list_brands` to `list_brands(self, active_only: bool = False)` (D-07). Default `False`
   preserves every existing call site's behavior; when `True`, filter out `is_active=False` brands.
   This is the SINGLE exclusion point — no per-call-site filtering anywhere (Don't-Hand-Roll rule).
2. Add `set_active(self, brand_key: str, is_active: bool) -> Optional[DynamicBrand]` (D-05/D-06):
   idempotent set (not toggle); `.lower()`-normalize the key; return None if key absent (→ 404 at the route);
   on match, set the flag and persist via the existing `_save(brand)` path (reuses Supabase upsert / brands.json write).

Deactivation only sets the flag (D-05) — NO active monitor cancellation here (that is `delete_brand`'s
behavior, explicitly out of scope per D-05). Exclusion happens because consumers enumerate via
`list_brands(active_only=True)` on their next cycle (wired in Plan 03).

Purpose: One chokepoint guarantees that a deactivated brand disappears from search, scheduler, monitoring
and export without touching any of those call sites' logic — and reactivation is immediate on the next call.

Output: Modified `services/brand_service.py`. Turns RED tests from Plan 00 green
(test_brand_active.py: TestListBrandsActiveOnly, TestSetActive).
</objective>
