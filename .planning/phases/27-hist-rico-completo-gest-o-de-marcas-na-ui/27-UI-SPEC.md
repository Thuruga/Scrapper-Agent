## Component & Interaction Contract

### A. `HistoryList` — reusable per-tab section (HIST-02, D-01/D-02/D-03/D-06)

**Build ONE shared presentational component** parameterized by type; placement stays per-tab (D-01 honored by where it is mounted, not by duplicating it). Resolves RESEARCH Open Question 1.

```
<HistoryList
  type="search" | "cross"
  onReopen={(jobId) => void}   // bubbles up to App.handleReopen
/>
```

**Placement (Claude's discretion, D-01):** a **collapsible `GlassCard` panel mounted ABOVE the results container**, inside each page's `.page-content`, after the search-bar `GlassCard`. Collapsed by default to stay unobtrusive (CONTEXT: "keep it unobtrusive"). Header row: `Histórico de buscas` + count badge + chevron toggle (`ChevronDown`/`ChevronRight`, already imported).
- `SearchPage`: mount with `type="search"`.
- `CrossMarketplacePage`: mount with `type="cross"`.

**Data fetch:** call `ApiClient.getHistoryList()` on mount, after a successful `handleSearch` (RESEARCH Pitfall 4 — refetch so the just-created entry appears), and after a delete. Filter client-side by `type` (RESEARCH: no `?type=` param needed).

**Each row reuses `.brand-item` geometry.** Layout left→right:
1. **Label** (`.brand-name-text`, weight 700):
   - `type==="cross"`: keep `"SKU: {query}"` (strip nothing; the stored `query` is already `"SKU: …"`).
   - `type==="search"`: compose in the FE from the record's `brands` + `query` (D-02; RESEARCH Pitfall 2 — `query` is the raw term, never a pre-composed label). Format: `{first 2 brand names joined ", "} · {N} marcas — "{query}"`. Example: `Reserva, Aramis · 3 marcas — "polo piquet"`. If `query` empty, drop the trailing `— "…"`. If `brands.length <= 2`, drop the `· N marcas` suffix.
2. **Type badge** (`.monitor-badge` style): "Comparativa" (primary tint) or "SKU" (accent tint).
3. **Date/time** (muted meta, `.brand-domain-text` style): format `created_at` as `DD/MM/YYYY HH:mm` (pt-BR).
4. **Status badge** (`.monitor-badge` style): "Concluída" (success), "Falhou" (error), "Em andamento" (warning).
5. **Delete button** (`.btn-icon .text-error`, `Trash2` size 18) — `ApiClient.deleteHistory(job_id)` → refetch list. Confirmation per copy contract.

**Row interaction states (D-06):**
- `status === 'COMPLETED'`: entire row is a clickable button → `onReopen(job_id)`. Hover affordance: subtle `--primary` border/background lift. `cursor: pointer`. Keyboard: row is a real `<button>` (or `role="button"` + `tabIndex=0`), activates on Enter/Space.
- `status === 'FAILED'`: NOT clickable. Reduced opacity 0.7, `cursor: default`, error badge shown, no reopen affordance.
- `status === 'PENDING'`: NOT clickable. "Em andamento" badge with a small `RefreshCw .animate-spin` icon, `cursor: default`.
- Delete button is always clickable and must `stopPropagation` so it never triggers reopen.

**Reopen flow (D-04/D-05, SC#2):** clicking a COMPLETED row calls `onReopen(job_id)` → bubbles to `App.handleReopen(jobId, type)` which `setActiveTab(type)` + `setPreloadedJobId(jobId)`. The destination page's existing `useEffect([preloadedJobId])` (`App.tsx:651` / `:974`) loads `getHistoryDetail` and **overwrites current results directly** (D-05). No re-scrape. Because the page already calls `onClearPreloadedJob()` on a fresh `handleSearch` (`App.tsx:678/1045`), the prop self-clears.

### B. App-level reopen wiring (HIST-02, SC#2 — MANDATORY)

`App.tsx` MUST own and propagate `preloadedJobId` (SC#2 names `App.tsx` literally). Add:
- `const [preloadedJobId, setPreloadedJobId] = useState<string | null>(null);`
- `handleReopen(jobId, type)` → set tab + set preloadedJobId.
- `renderTab`: pass `preloadedJobId` + `onClearPreloadedJob={() => setPreloadedJobId(null)}` to BOTH `<SearchPage>` (`App.tsx:1798`) and `<CrossMarketplacePage>` (`App.tsx:1799`). They already declare these props.
- The `onReopen` callback the `HistoryList` receives is `(jobId) => handleReopen(jobId, type)` — type is known at mount per tab, so the row only needs `jobId`.

**UI consequence to record (per objective):** a single shared `preloadedJobId` is safe because tabs are mutually exclusive (only one renders). Optionally clear it on manual tab switch to avoid a stale reopen.

### C. Brand management extension (MGMT-02, D-08/D-09/D-10)

**EXTEND the existing "Marcas Cadastradas" `GlassCard` + `.brand-item` rows (`App.tsx:1421-1450`). Do NOT redesign.** Keep the add-brand form (left card) and the existing delete button untouched in behavior.

Add to `frontend/src/api/client.ts` (RESEARCH §MGMT-02):
```ts
static setBrandActive(brandKey: string, isActive: boolean) {
  return this.request(`/brands/${brandKey}/active`, {
    method: 'PATCH',
    body: JSON.stringify({ is_active: isActive }),
  });
}
```

**Per-row additions inside `.brand-actions`:**
1. **Active/inactive toggle** — a switch (or `.btn-icon` with `Power` icon) calling `ApiClient.setBrandActive(b.brand_key, !b.is_active)` then `onRefresh()`. ON state uses `--primary`; OFF state muted. aria-label per copy contract. Toggle is **instant/reversible** (D-10), no confirmation.
2. Existing delete button (`.btn-icon .text-error`, `Trash2`) stays as the **permanent, confirm-gated** action (D-10).

**Inactive visual distinction (D-09):** when `b.is_active === false`, the `.brand-item` gets reduced opacity (~0.55) on the `.brand-info` block **plus** an "Inativa" badge (`.monitor-badge` warning tint) next to `.brand-name-text`. The row stays fully interactive (so it can be reactivated) — only the info block is dimmed, not the actions.

**Virtual marketplace guard (RESEARCH landmine, A1):** the three injected virtual marketplaces — `mercado_livre`, `netshoes`, `amazon` — have NO backend brand record; a PATCH would 404. **Hide the toggle for these three keys.** Render their delete state as-is (they already render). Guard: `const VIRTUAL = ['mercado_livre','netshoes','amazon']; const canToggle = !VIRTUAL.includes(b.brand_key);` — only render the toggle when `canToggle`.

> Note: the list already shows all brands because `GET /brands/` returns inactive ones (Phase 25 opt-in). No fetch change needed; only render the distinction.

## Accessibility Basics

- COMPLETED history rows are real `<button>`s (or `role="button"` + `tabIndex=0`), activatable by Enter/Space (D-06: only COMPLETED — others are non-interactive, not focusable as actions).
- Delete + toggle buttons have explicit `aria-label`s (icon-only) per copy contract; delete `stopPropagation`.
- Status conveyed by badge text + icon, not color alone (color-blind safe).
- Toggle exposes `aria-checked` / pressed state.
