## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser (SettingsPage) → PATCH /brands/{key}/active | Toggle sends a validated boolean; `brand_key` is a path param used in a dict lookup server-side |
| browser → DELETE /brands/{key} | Permanent delete behind a `confirm()` (unchanged) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-27-02-01 | Tampering | Arbitrary `brand_key` in PATCH path | mitigate | `set_active` returns None for unknown key → route raises 404 (no dict creation on miss); already covered by `tests/test_brand_active.py::test_set_active_unknown_key_returns_none`. Client surfaces the thrown error |
| T-27-02-02 | Tampering | PATCH body `{ is_active }` | mitigate | `BrandActiveUpdate` Pydantic model validates the boolean at the route boundary (V5 Input Validation) |
| T-27-02-03 | Spoofing/Elevation | Toggling a virtual marketplace that has no record | mitigate | UI hides the toggle for `mercado_livre`/`netshoes`/`amazon`; even if bypassed, server 404s (no silent record creation) |
| T-27-02-04 | Information Disclosure | Inactive brand data rendered in UI | accept | Same API-key gate as all brand data; React auto-escapes; no new exposure |
| T-27-02-SC | Tampering | npm installs | accept | This plan installs ZERO packages (RESEARCH Package Legitimacy Audit: zero external packages). `Power` is from already-installed lucide-react. No legitimacy gate required |

No HIGH threats. Consumes an existing, tested endpoint; React auto-escaping covers XSS; no new auth surface.
