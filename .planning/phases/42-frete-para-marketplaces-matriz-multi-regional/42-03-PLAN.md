<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser client → /search/calculate-shipping-matrix | Frontend sends brand_key + product_url (no CEP) to the on-demand matrix route |
| Cross-marketplace enrichment → engine shipping | Backend surfaces engine shipping output (incl. block signal) onto product dicts for the UI |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-42-01 | Spoofing/Tampering (SSRF) | product_url sent by requestMatrix | mitigate | The backend route (Plan 02) enforces `is_url_allowed_for_brand` and returns 400 on mismatch; the frontend sends only the persisted product URL. No client-side trust. |
| T-42-03 | Tampering (false-zero shipping) | blocked-state rendering + enrichment | mitigate | Blocked renders the explicit "Bloqueado (anti-bot)" label; enrichment never sets shipping_price=0.0 on a block, and the UI never substitutes a fake R$ 0,00 for a non-available region (UI-SPEC acceptance). |
| T-42-07 | Information Disclosure (XSS/formula) | Region/state text rendered in the modal | accept | Text is React-escaped JSX (no dangerouslySetInnerHTML); region/capital/CEP come from server-curated cep_matrix.json, not user input. Low risk, no new sink introduced. |
| T-42-SC | Tampering | npm/pip/cargo installs | mitigate | Zero new packages; icons/components reuse already-imported lucide-react + hand-rolled CSS (RESEARCH.md Package Legitimacy Audit: "Not applicable"). No install task; no legitimacy checkpoint. |
</threat_model>
