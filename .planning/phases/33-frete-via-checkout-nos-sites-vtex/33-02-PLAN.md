<objective>
Wire the Wave 1 pure parser into the live VTEX checkout path and expose the default CEP to the frontend. Rewrite `_fetch_shipping` to pair each SKU with its own seller, perform exactly one bounded retry inside the existing semaphore, classify results into explicit states, and populate the additive `shipping_options` plus the legacy primary fields. Add a read-only `GET /search/config` endpoint that surfaces `DEFAULT_CEP`, and prove the multi-option contract serializes correctly.

Purpose: This is the reliability + contract pass for FRET-05. It removes the hardcoded `seller="1"`, the unfiltered `min(price)`, and the single-failure-state collapse; it adds resilient retry/isolation so a failing store cannot stall the search (T-33-03), keeps the simulation URL anchored to the persisted brand domain (T-33-01, SSRF), and keeps CEP/payloads out of logs (T-33-02). The default-CEP endpoint gives the frontend a safe source for the visible destination (D-04).

Output: Rewired `_fetch_shipping`, a read-only config endpoint, extended client characterization tests, and a new API/contract test file — all green, with the 5 baseline shipping tests preserved.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → /search (POST/GET) | CEP and query cross from the untrusted client; validated by the existing Pydantic pattern, sent only in JSON. |
| /search → VTEX checkout simulation | Outbound request whose host MUST be the persisted brand domain, not a caller-supplied value. |
| client → /search/config | Read-only outbound config; must expose no secret. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-33-01 | Spoofing/SSRF | `_fetch_shipping` simulation URL; `GET /search/config` | mitigate | Build the simulation URL only from the `domain` derived from the persisted VTEX brand (never from request body); the config endpoint takes no input and returns only `default_cep`. CEP sent in JSON body, never interpolated into a URL. |
| T-33-02 | Information Disclosure | `_fetch_shipping` logging | mitigate | Log only brand key, HTTP status, and attempt count; never the full simulation payload or the user CEP at info/error level. |
| T-33-03 | Denial of Service | `_fetch_shipping` retry/concurrency; `asyncio.gather` batch | mitigate | Bounded timeout, exactly one retry, retry stays inside `self.semaphore`; per-product exceptions absorbed so a failing/slow store cannot stall or cancel sibling quotes. |
| T-33-04 | Tampering | SLA payload → ShippingInfo (via Wave 1 parser) | mitigate | `_fetch_shipping` delegates all SLA parsing/validation to the validated Wave 1 helpers (channel/cents/estimate checks) before constructing models. |
| T-33-SC | Tampering | npm/pip/cargo installs | accept | No package installation in this plan (uses existing aiohttp/pydantic/pytest). Nothing to verify. |
</threat_model>
