<objective>
Deliver the operator-facing VTEX shipping experience per 33-UI-SPEC.md: load the backend default CEP, show it as a visible, editable destination labeled "CEP de entrega", block search/export on an invalid edited CEP, and render every `shipping_options` entry inside each VTEX product card — distinguishing free shipping, no-delivery, and temporary failure, while keeping product price and freight visually separate and preserving legacy-history rendering.

Purpose: This completes FRET-05 end-to-end at the UI. It honors D-04 (visible default, never silent), D-05 (block invalid CEP with a clear error), D-06 (session-scoped CEP, resets on reload), D-07 (auto-shipping on every valid search), D-08 (price/freight separated, no total on this surface), D-09–D-12 (all delivery options, ordered, free highlighted, pickup never shown, faithful units). The one-time init flag prevents a late config fetch from clobbering a user-edited CEP (RESEARCH pitfall 8).

Output: A `getSearchConfig` client method, a `cepInitialized` store flag with one-time init, the rewired CEP field + shipping list in `App.tsx`, and supporting `App.css` — all type-checking, linting, and building clean.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → /search/config | Read-only fetch of the default CEP; no secret returned. |
| browser → /search (POST) | CEP submitted; the frontend blocks an invalid edited CEP before sending. |
| VTEX response → card render | `shipping_options` is backend-validated; the UI renders text/values without executing payload content. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-33-01 | SSRF (defense-in-depth) | CEP submission from App.tsx | mitigate | The frontend never sends a checkout host; it sends only the validated CEP digits in the JSON body via `ApiClient.search`. The backend (33-02) anchors the simulation URL to the persisted brand domain. |
| T-33-02 | Information Disclosure | client error handling | accept | The UI surfaces only the defined copy strings; it does not log the CEP or payloads. No new logging added. |
| T-33-04 | Tampering | rendering untrusted `shipping_options` | mitigate | React text rendering escapes content; the UI renders only validated string/number fields produced by the Wave 1/2 backend — no `dangerouslySetInnerHTML`, no eval. |
| T-33-SC | Tampering | npm installs | accept | No package installation (UI-SPEC §Registry Safety — reuse React/Zustand/Lucide/CSS). Nothing to verify. |
</threat_model>
