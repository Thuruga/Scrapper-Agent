<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator → `POST /brands/` → `detect_engine(domain)` | The brand domain is operator-supplied input; it becomes a URL fetched/rendered by the backend. |
| `detect_engine` → `BrowserManager.fetch_html` → live external site | The SFCC probe renders an attacker-influenceable home page in a real headless browser. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-30-01 | Spoofing | SFCC marker match in `detect_engine` | mitigate | Verdict requires the EXCLUSIVE asset hosts `demandware.static`/`demandware.edgesuite.net` (D-02), not the spoofable bare substring `demandware`. A non-SFCC page that merely mentions the word `demandware` does not match, so a brand cannot be mislabeled onto the wrong engine. |
| T-30-02 | Information Disclosure (SSRF) | `BrowserManager.fetch_html(f"https://{domain}")` | accept | Brand registration is an authenticated, operator-only, rare event (not a public hot path); the operator already chooses the domain to onboard. URL is forced to `https://` scheme. Internal-network SSRF hardening is out of L1 scope for an operator-trusted admin action; recorded as accepted residual risk. The existing HTTP probes (`allow_redirects=False`, T-25-01) already establish the redirect-discipline baseline. |
| T-30-03 | Denial of Service (resource exhaustion) | Headless browser render per unknown domain | mitigate | The probe is LAST-RESORT (D-07): it only fires after all cheap HTTP probes fail, on a rare registration event. `fetch_html` carries a bounded `timeout` (30s default) and closes the page/context/browser in a `finally`. Any timeout/failure degrades to `"unknown"` (D-04) rather than retrying unboundedly. |
| T-30-04 | Tampering | Malicious rendered content crashing detection | mitigate | The entire SFCC probe is wrapped in `try`/`except Exception` → `logger.debug` → fall through to `"unknown"` (D-04). Malformed/hostile HTML cannot crash `detect_engine` or down the request. |

No npm/pip/cargo installs in this plan — package legitimacy gate not applicable.
</threat_model>
