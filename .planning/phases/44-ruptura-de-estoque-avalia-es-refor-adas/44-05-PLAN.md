<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser UI -> authenticated API | User clicks trigger authenticated API calls through `ApiClient.request`. |
| monitor product card -> backend action | UI passes monitor_id and scan_product_id only. |
| backend state -> UI rendering | Returned provider text/comments may contain untrusted text. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-44-19 | Tampering | frontend action payload | mitigate | Client methods pass only monitor_id, scan_product_id, and optional max_pages; no URL/domain/provider/quantity payload. |
| T-44-20 | Denial of Service | accidental bulk UI actions | mitigate | Buttons act on one product at a time and are disabled while that product action is in flight. |
| T-44-21 | Information Disclosure | rendering review comments | mitigate | Render normalized compact comment fields only; do not expose provider raw payloads. |
| T-44-22 | Spoofing | API auth | transfer | Existing `ApiClient.request` sends `X-API-Key`; backend authenticated router enforces the key. |
</threat_model>
