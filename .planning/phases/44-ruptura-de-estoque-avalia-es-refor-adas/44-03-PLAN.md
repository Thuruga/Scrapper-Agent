<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| API caller -> stock-depth action | Caller can choose monitor_id and scan_product_id, but not domain/URL/quantity/provider. |
| scan product artifact -> browser probe | Persisted product URL crosses into Playwright navigation and cart APIs. |
| backend -> competitor cart | Low-frequency outbound cart interaction with a competitor storefront. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-44-09 | Tampering / SSRF | `probe_scan_product_stock_depth` | mitigate | Resolve brand from persisted monitor, load product from persisted scan artifact, validate URL host against persisted brand domain, and reject caller-supplied domain/URL/quantity. |
| T-44-10 | Denial of Service | stock-depth provider execution | mitigate | One product per action, `STOCK_PROBE_THROTTLE_SECONDS`, `MAX_STOCK_DEPTH_PROBES_PER_BRAND`, short timeout, no fan-out loop. |
| T-44-11 | Information Disclosure | provider logs | mitigate | Log provider state/status class only; do not log cart payloads, cookies, or full provider responses. |
| T-44-12 | Tampering | stock-depth state mapping | mitigate | Persist explicit state and only persist numeric estimate for real provider evidence; timeout/block/unsupported never becomes zero. |
| T-44-13 | Denial of Service | Playwright lifecycle | mitigate | Use ephemeral page/context/browser and `finally` cleanup verified by tests. |
</threat_model>
