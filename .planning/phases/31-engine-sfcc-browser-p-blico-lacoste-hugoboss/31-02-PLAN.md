<objective>
Implement the SFCC search core — the work that closes Phase 31 against the four Success Criteria. Build `SFCCEngine` as a direct analog of `ShopifyEngine`: a thin engine that renders the store's native search page via `BrowserManager` then enriches via PDP (D-03), against the BR storefronts `lacoste.com.br` / `hugoboss.com.br` with price extracted natively in reais (D-01). It extracts candidate PDP URLs (`parse_search_results`), enriches each up to `max_results` PDPs concurrently with a `Semaphore(3)` throttle (D-07/D-08), parses each PDP via `parse_pdp`, runs the Quality Gate (`validate_single`) + gender filter, and returns a `BrandSearchResult`. `calculate_shipping` returns `None` (D-09). Split the `factory.py` guard so `engine="sfcc"` instantiates the engine while `engine="wake"` still raises (Pitfall 4).

Purpose: This is the SC-1..SC-4 core that the critical sequencing requires FIRST. Catalog/category discovery (D-05) is deferred to Wave 2 and must not block this delivery.
Output: `sfcc_engine.py` (search + shipping + full BaseEngine contract), `factory.py` (guard split). The Wave 1 tests in `test_sfcc_engine.py` (TestSFCCFactory + TestSFCCEngineSearch) flip from RED to GREEN.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator search query → search URL | User-derived query is interpolated into the SFCC search URL |
| SFCC storefront → SFCCEngine | Rendered HTML (possibly partial/blocked) crosses into the engine |
| engine selection (brand.engine string) → factory | The persisted `engine` field routes to a concrete engine |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-31-03 | Spoofing | `SFCCEngine.search` constructed search URL | mitigate | URL-encode the query; keep navigation same-domain (`https://www.{brand.domain}/...`); log the final resolved URL; never build the URL from un-sanitized external input beyond the search term (open-redirect mitigation) |
| T-31-04 | Denial of Service | per-PDP enrichment under anti-bot block / partial HTML | mitigate | per-PDP try/except swallows individual failures (logged), `Semaphore(3)` throttle limits concurrent browser hits; `validate_single` Quality Gate rejects products missing url/raw_title/price_full/image_url so partial HTML yields no corrupt product |
| T-31-05 | Elevation of Privilege | factory routing for `wake` | mitigate | guard split keeps `wake` raising NotImplementedError (caught by `_search_one` `except Exception` → BrandSearchResult.error) — prevents silent VTEXEngine misroute (Pitfall 4) |
| T-31-06 | Tampering | false "Frete Grátis" badge from shipping fields | mitigate | `calculate_shipping` returns None and the engine never sets `is_free_shipping`/`shipping_price` — frontend badge (App.tsx) does not fire (CRQ-4) |
| T-31-SC | Tampering | npm/pip/cargo installs | accept | No new packages; all deps already pinned in backend/requirements.txt |
</threat_model>
