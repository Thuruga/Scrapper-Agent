## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator input → SKU field (client) | Untrusted SKU string; frontend regex is a UX gate only |
| SKU field (client) → backend SKU-search endpoint | The real trust boundary; backend must validate independently |
| polled GET /monitor/categories → auto-open modal | Read-only category state; no privileged action triggered by the poll beyond reusing existing read endpoints |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-38-04 | Tampering | SKU regex bypass (client-side only) | accept (out of scope to fix) | ASVS V5: the new `^ML\.05\.\d{7}$` regex is a UX validation, NOT a security control. The backend SKU-search route already validates/sanitizes independently (RESEARCH.md Security Domain) — frontend validation must never be treated as sufficient. Flagged, not fixed (backend SKU handling unchanged this phase). |
| T-38-05 | Denial of Service (self-inflicted) | Unbounded auto-sweep poll timer | mitigate | Poll has a max-attempts cap (~20/~60-100s) and clears on unmount, so a hung scan cannot leave an infinite client-side timer (RESEARCH.md Open Question 2). |
| T-38-SC | Tampering | npm installs | mitigate | N/A — zero package installs this plan (`RefreshCw`/`AlertTriangle`/`History` already imported; sonner already installed). |
