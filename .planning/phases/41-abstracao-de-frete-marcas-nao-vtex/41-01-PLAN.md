<objective>
Create and run Spike 011 to prove whether the two target non-VTEX providers can return real freight publicly: Shopify/Buckman and Wake/Richards. The spike must produce a reproducible `REPORT.md` with a clear GO/NO-GO per provider before any production provider code is written.

Purpose: Avoid building a provider on guessed checkout behavior. Shopify has official Ajax Cart shipping-rate endpoints, and Wake has an official Fbits quote endpoint, but the actual stores may require session, product identity, token scope or store-specific paths. This plan gathers that evidence once, at low impact, and turns it into implementation constraints for Plans 02 and 03.

Output: `.planning/spikes/011-non-vtex-shipping/experiment.py` and `REPORT.md`, with provider verdicts and normalized sample rate fields.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| spike -> live storefronts | Outbound requests to Buckman/Richards; must be low-impact and public. |
| product URL -> provider request | URL must come from brand/domain discovery, not arbitrary user input. |
| report/logs | Must not leak unnecessary CEP or request body details. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-41-01 | Denial of Service | Shopify/Wake live probes | mitigate | One product, bounded timeout, bounded retries/polls, no concurrent fan-out, cart cleanup. |
| T-41-02 | Information Disclosure | Spike output/logging | mitigate | Do not print full CEP or full request payload at info/error; report signatures instead of raw bodies when sensitive. |
| T-41-03 | Authorization boundary | Wake quote endpoint | mitigate | Use only existing public/storefront token path; if private scope required, record NO-GO. |
| T-41-04 | Data integrity | Verdict criteria | mitigate | GO requires real price + delivery text/date twice; null/empty never becomes free shipping. |
</threat_model>
