<objective>
Deixar clara a passagem de tempo no gráfico "Histórico de Variações" (componente `PriceChart` em `frontend/src/App.tsx`).

Hoje o eixo X usa `dataKey="time"` com strings `HH:MM` — um eixo **categórico** que espaça todos os pontos igualmente, independentemente do tempo real entre eles, e nunca mostra a data. Os dados reais confirmam o problema: as entradas de histórico cruzam múltiplos dias (ex.: 2026-06-23, 2026-07-01, 2026-07-04) e são desenhadas com espaçamento idêntico, distorcendo a leitura da passagem de tempo.

Purpose: O usuário reportou "Não está claro a passagem de tempo nos gráficos". A correção converte o eixo X para uma escala **temporal proporcional** (recharts `type="number"` + `scale="time"`), adiciona rótulos com data quando o histórico cruza dias, garante tooltip com timestamp completo, e mostra o intervalo início→fim — sem trocar de biblioteca de gráfico nem tocar em outros componentes.

Output: `frontend/src/App.tsx` com `PriceChart` refatorado.
</objective>

  <action>
Refatore APENAS o componente `PriceChart` (aprox. linhas 632-704). Não altere o consumidor nem os imports do recharts (todos os símbolos necessários já estão importados).

1. Transformação de dados (substitui o `data`/`chartData` atual):
   - Mapeie cada entrada para `{ ts: new Date(h.timestamp).getTime(), price: h.price }`.
   - Filtre pontos com `ts` NaN (`Number.isNaN`), depois ORDENE ascendentemente por `ts` — a linha deve ser cronológica mesmo se o histórico vier fora de ordem.
   - Guarde `first = points[0]?.ts` e `last = points[points.length - 1]?.ts`.

2. Caso de 1 único ponto (preserva o comportamento atual de "linha estável"): se `points.length === 1`, gere `chartData = [points[0], { ...points[0], ts: points[0].ts + 60_000 }]` (segundo ponto sintético 60s depois, mesmo preço) para o domínio numérico não colapsar. Caso contrário `chartData = points`.

3. Detecção multi-dia: `const spansMultipleDays = first != null && last != null && new Date(first).toDateString() !== new Date(last).toDateString();`

4. Formatadores (locale pt-BR):
   - `fmtTick(ts)`: se `spansMultipleDays` → `new Date(ts).toLocaleString('pt-BR', { day: '2-digit', month: '2-digit', hour: '2-digit', minute: '2-digit' })`; senão → `new Date(ts).toLocaleTimeString('pt-BR', { hour: '2-digit', minute: '2-digit' })`.
   - `fmtFull(ts)`: `new Date(ts).toLocaleString('pt-BR', { day: '2-digit', month: '2-digit', year: 'numeric', hour: '2-digit', minute: '2-digit' })` — usado no tooltip e na legenda de intervalo.

5. XAxis: troque `dataKey="time"` por `dataKey="ts"` e adicione `type="number"`, `scale="time"`, `domain={['dataMin', 'dataMax']}`, `tickFormatter={fmtTick}`, e `minTickGap={24}` (evita sobreposição dos rótulos, que agora podem incluir data). Mantenha stroke/fontSize/tickLine/axisLine/dy existentes.

6. Tooltip: atualize `labelFormatter` para `(label) => fmtFull(Number(label))` (o label agora é o timestamp numérico, não a string). Mantenha o `formatter` de preço existente (`R$ ${value.toFixed(2)}`).

7. Linha: mantenha `<Line ... dataKey="price" ... />` inalterada (o eixo Y não muda).

8. Legenda de intervalo (clareza da passagem de tempo): no cabeçalho, ao lado de `{N} registros`, quando `points.length > 1`, renderize uma linha discreta abaixo do título com `{fmtFull(first)} → {fmtFull(last)}` (mesmo estilo mudo/pequeno já usado no header: fontSize ~11px, cor rgba(255,255,255,0.4)). Reutilize `points.length` como contagem de registros.

Regra: NÃO adicionar dependências novas (nada de date-fns); usar apenas `Intl`/`toLocaleString` nativos. Sem `any` novo além do já existente na assinatura `history: any[]`. Manter Clean Code, sem over-engineering.
