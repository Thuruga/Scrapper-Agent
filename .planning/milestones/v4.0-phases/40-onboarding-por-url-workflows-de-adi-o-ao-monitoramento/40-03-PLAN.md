<objective>
Make "Adicionar ao monitoramento" idempotent (UX-04, D-08/D-09). Today `POST /monitor/start`
mints a fresh uuid job_id on every call with no duplicate check. This plan adds a dedup scan to
`start_monitor`: comparing `normalize_url(url)` (from Plan 01) + `brand.lower()` against existing
monitors. Already-active → no-op `already_active`; existing-but-stopped → reactivate; otherwise →
create. `POST /monitor/start` unpacks the returned status and includes it in the JSON response so
the frontend (Plan 05) can toast the correct message.

Per RESEARCH Pattern 5 / Assumption A1 (verified by reading `_monitor_loop`): `duration_hours` is
stored but NEVER enforced — the loop stops only on `config.active=False`. So D-06 "indefinite" is
already the current behavior; this plan introduces NO new expiry mechanism and the 1-click default
(`interval=10`, `duration=24`) is fine.

Purpose: One product per (normalized url + brand) in the price monitor, from any of the 3 surfaces.
Output: dedup-aware `start_monitor`; status-returning `POST /monitor/start`; extended tests.
</objective>
