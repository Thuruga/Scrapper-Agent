<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `frontend/API client -> /sortiment/* routes` | Operator actions can trigger manual runs and registry updates, so the backend must resolve persisted category state server-side. |
| `APScheduler/manual trigger -> sortiment_snapshot_service` | Background and manual execution compete for the same local snapshot directories and must not overlap unsafely. |
| `brand site scrape output -> bucket aggregator` | Upstream attribute values are noisy and cannot be trusted as-is for truthful assortment analytics. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-45-04 | Denial of Service | scheduler/manual run execution | mitigate | Register a dedicated sortiment APScheduler job with `max_instances=1` and `coalesce=True`, and add a runtime lock/guard so cron-vs-manual overlaps return a busy status instead of double-running. |
| T-45-05 | Tampering | `routes_sortiment.py` run/update endpoints | mitigate | Accept only persisted sortiment category IDs and server-owned enable flags; resolve URL/brand/category data from the registry instead of trusting request payloads. |
| T-45-06 | Integrity | dashboard delta assembly | mitigate | Centralize baseline detection and delta calculation on the backend so missing previous snapshots return explicit baseline state rather than fabricated zero deltas per D-15/D-16/D-17. |
| T-45-07 | Integrity | upstream Hugo Boss/category scan output | accept | Treat sparse or zero Hugo Boss category data as inherited upstream risk from the pending todo; surface truthful aggregates and avoid a new remediation branch in Phase 45. |
| T-45-SC | Tampering | npm/pip/cargo installs | accept | No new package-manager installs are required for Phase 45. |
</threat_model>
